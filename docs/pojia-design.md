# 破甲：深入而可核验的逆向分析

## 专家会补上的事情

先定义可证伪的问题与失败条件，固定目标构建及工具身份；区分观察、推导、运行验证和未知。围绕最短调用链解释输入、运算、分支、状态和输出，再主动寻找反例。遇到未覆盖或缺失证据时保留不确定性，不用工具数量或报告篇幅替代深度。

## 从哪些原始素材开始

原始二进制/安装包及 SHA-256，指令字节、汇编/CIL、符号/导入、元数据与交叉引用；授权环境中的原始请求响应、崩溃记录与关联日志。源码、构建命令、配置和已知答案单独保留用于核验。既有总结用于定位问题，不替代原始证据。

## 具体方法和工具

REA MCP/CLI 用于取得可定位的原始分析结果；Ghidra/IDA/Hopper、JADX 或静态 PE/CLI 读取器按目标选择。用调用链与数据流分析、原始字节核对、边界输入、固定 seed 差分测试和负对照验证假设。每次只增加能消除当前不确定性的工具。

本机实测聚焦自建 .NET 单函数：Windows 自带 C# 编译器生成原始 EXE，REA 读取元数据/CIL，CLR Reflection 独立读取同一方法的 CIL 字节，Python 数学实现与 EXE 输出差分，并故意改变一个常量检验测试能否识别错误。

## 除你我之外，什么能证明正确

可复跑命令、保存的原始输出、样本及输出哈希、确定性机器断言、已知答案和负对照，以及不知预期答案的复核者。模型意见与同后端的 CLI/MCP 一致不算独立事实证明。有限输入通过也不等于全域形式证明。

## 重写后的题目

> 安装并固定来源可追溯的 REA，为本地授权逆向开发“破甲”Skill。围绕一个具体行为，从原始样本建立“证据 → 假设 → 验证 → 结论”的链条；通过已知答案样本、反例和独立复核验证结果。交付可重跑的实测记录、明确的能力边界和可安装技能，不用扩大工具清单代替分析深度。

## 交付验收

- REA 的版本、npm integrity、源码提交及两者关系可查；注册配置有备份且只改变授权范围。
- 独立本地 MCP 客户端完成握手、工具目录和真实样本调用；与当前聊天是否已连接分别报告。
- 原样本 SHA-256 与 REA 身份记录一致；方法 CIL 有字节级独立核对。
- 固定输入语料通过差分，错误假设至少有一个反例；错误/缺失数据不能得到成功结论。
- 技能格式、脚本与实际行为验证通过；触发词是“破甲”或 `$pojia`。
- 不承诺所有格式均已实测，不代替授权，不生成隐匿入侵或盗用服务的流程。
