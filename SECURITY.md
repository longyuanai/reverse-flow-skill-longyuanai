# Security Policy

## Supported Versions

We provide security updates and patches for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| 1.0.x   | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

As a security analysis and reverse engineering skill suite, we take vulnerabilities in our own codebase, parser engines, and execution harnesses very seriously.

If you discover a security vulnerability (such as a parser buffer overflow, arbitrary code execution, path traversal in evidence manifests, or denial of service on malformed binaries), **please do NOT report it via public GitHub issues**.

Instead, please send a report to our security contact:

- **Security Contact**: `1507205727@qq.com`
- **PGP/Encrypted Communications**: Available upon initial contact.

### Please include:
1. Description of the vulnerability and attack vector.
2. Proof of concept (PoC) or reproducer artifact.
3. Affected versions, OS, and Python environments.
4. Suggested mitigation or patch, if known.

### Response Timeline
- **Initial Response**: Within 24 hours.
- **Triage & Confirmation**: Within 48 hours.
- **Patch Release & Advisory**: Within 7 business days depending on severity.

## Safe Harbor
We will not pursue civil or criminal action against researchers who discover and report vulnerabilities in compliance with responsible disclosure principles, provided no malicious exploitation or data destruction has occurred.
